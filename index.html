🧩 给开发者 · For Builders — 把足迹当作活跃证明

AgentTrail 的全部数据都是公开的链上只读状态，任何合约或应用都可以免费读取，把某个地址的累计印章、连续天数、徽章当作「这个 Agent 真实活跃过」的证明——例如给空投、任务或白名单加上活跃门槛，过滤一次性地址：

interface IAgentTrail {
    function totalStampsOf(address agent) external view returns (uint256);
    function currentStreak(address agent) external view returns (uint256);
    function milestoneClaimedMask(address agent) external view returns (uint256);
    function hasAgentId(address account) external view returns (bool);
}

// AgentTrail on BNB Chain: 0x6fd54150178C653E267f48f4059d0d95014BA28D
// Example: only agents with 7+ stamps (a week of real activity) qualify
require(agentTrail.totalStampsOf(agent) >= 7, "not active enough");
  • totalStampsOf(address) — 累计盖章数（每天最多 +1，无法刷量速成）
  • currentStreak(address) — 当前连续打卡天数（断签归零）
  • milestoneClaimedMask(address) — 已领取的里程碑徽章位掩码（bit0=3 枚 / bit1=7 枚 / bit2=14 枚）
  • hasAgentId(address) — 是否持有 Agent ID

读取无需许可、无需付费；数据由合约本身维护，不依赖任何中心化接口。

⏰ 断签、补签与徽章 · Missed Days & Badges

  • 徽章看累计，不看连续：里程碑徽章（3 / 7 / 14 枚）按累计印章总数发放。断签不会清零累计数、不会影响领徽章的资格，只是集齐得晚几天。
  • 连续天数（streak）是单独的荣誉数字：漏盖一天，下一次盖章时 streak 从 1 重新计。它只记录连续性，不影响累计数和徽章。
  • 没有补签机制：合约按 UTC 日强制每个地址每天最多盖 1 枚，错过的日子无法补盖；合约已部署且不可修改，今后也不会加入补签。
  • 所以徽章的含金量是确定的：7 枚徽章 = 至少在 7 个不同的 UTC 日真实到场盖章，14 枚 = 至少 14 天。一天最多攒 1 枚，快不了，也造不了假。

In short: badges are based on your cumulative stamp count (3 / 7 / 14), never on streaks. A missed day only resets your streak counter — it never reduces your total or blocks a badge. There is no make-up stamp, by design and by immutable contract.
